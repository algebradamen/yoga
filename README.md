# Edita's Yoga & Pilates Sessions

Static site generator for yoga and pilates session guides, live at **https://yoga.algebradamen.no**.

Each session is a YAML file. The build validates the files, then renders them into multilingual HTML pages (Norwegian, English and Spanish).

## Quick start

```sh
npm install
npm run watch        # generate + serve, auto-rebuild on changes
```

Open the URL printed by `serve` (usually http://localhost:3000).

## npm scripts

| Script | Description |
|---|---|
| `npm run generate` | Parse YAML → JSON, then render HTML into `dist/` |
| `npm run generate:json` | YAML → JSON only (`generated/`), with schema and duration checks |
| `npm run generate:html` | JSON → HTML only (`dist/`) |
| `npm run validate` | Schema-check YAML files (all, or the ones given as arguments) |
| `npm run serve` | Serve `dist/` locally |
| `npm run watch` | Generate + serve, rebuild on any YAML/script change |
| `npm run translate` | Translate every `.NO.yaml` file to English and Spanish with Claude |

`npm run dist` is an alias for `generate`.

## Adding a new session

1. Create `my-session.NO.yaml` in the project root. Norwegian is the source language.
2. Run `npm run generate`. The session appears on every front page. Where a translation is missing, the card links to the Norwegian page and shows a small **NO** tag.
3. Run `npm run translate` to create `my-session.EN.yaml` and `my-session.ES.yaml`, then review them.

See `SPEC.md` for the fields a session can use, and `track.schema.json` for the exact schema.

## Deployment

Every push to `main` builds the site and deploys it to GitHub Pages (`.github/workflows/deploy.yml`). The custom domain `yoga.algebradamen.no` is a CNAME to `algebradamen.github.io` and is configured under the repository's **Settings → Pages**. The build fails, and nothing is deployed, if a YAML file is invalid or its durations are off by more than 10%.

## Translating

`npm run translate` sends each `.NO.yaml` file to Claude once per target language, validates the result against the schema and writes `.EN.yaml` / `.ES.yaml`. Norwegian files are never modified. It prints a suggested `git commit` but does not commit.

Two backends are available:

| Backend | How to use | Authentication |
|---|---|---|
| Claude CLI (default) | `npm run translate` | Your normal `claude` login, or `ANTHROPIC_API_KEY` |
| Anthropic API | `TRANSLATE_BACKEND=api npm run translate` | `ANTHROPIC_API_KEY`, or the key in `api-key.txt` (gitignored) |

The **Translate tracks** workflow (`.github/workflows/translate.yml`) does the same in CI. Run it manually from the Actions tab; it commits and pushes new or changed translations to `main`, which then triggers a deploy. It needs the `ANTHROPIC_API_KEY` repository secret.

## Project layout

```
.
├── *.NO.yaml                 # Session sources (Norwegian)
├── *.EN.yaml, *.ES.yaml      # Translations (generated by `npm run translate`, then reviewed)
├── track.schema.json         # JSON Schema for session files
├── styles/yoga.css           # Shared stylesheet
├── images/                   # Decorative SVGs and favicon
├── scripts/
│   ├── parse-track-yaml.js   # YAML → JSON with schema and duration checks
│   ├── validate-track.js     # Shared validation (used by parse and translate)
│   ├── validate-yaml.js      # Standalone schema check (`npm run validate`)
│   ├── generate-html.js      # JSON → HTML
│   ├── i18n.js               # UI string translations
│   ├── watch.js              # Dev watcher
│   └── translate-tracks.js   # Claude-assisted YAML translation
├── Pilates Odda.pdf, Pilates-1-og-yin-1.docx, Yin yoga 60 minutter.docx,
│   yin-60-heart-kidney-meridian.md
│                             # Original session notes the YAML files were made from
├── .github/workflows/        # deploy, translate, and @claude helpers
├── generated/                # Intermediate JSON (gitignored)
└── dist/                     # Output site (gitignored)
```

## Output structure

```
dist/
├── index.html              # Front page (Norwegian, default)
├── index.en.html           # Front page (English)
├── index.es.html           # Front page (Spanish)
├── styles/yoga.css
├── images/
└── my-session/
    ├── index.html          # Norwegian (default)
    ├── index.en.html
    └── index.es.html
```

All links in the output are relative, so `dist/` works from any base path.
